# Architecture and operation

- Next.js Pages Router and Apollo server queries in `src/edoctor/server.ts`. Create a fresh Apollo client per request; never share authenticated caches. Paginate public products/posts. Missing backend may render empty configuration states; an outage must not replace a last-good cache with empty data.
- Public pages use ISR plus signed WordPress invalidation. Private basket/account responses use private,no-store. Search is Meilisearch via the React InstantSearch adapter, refreshed by one worker and atomically swapped after all tasks succeed.
- Browser basket stores references/quantities and indicative prices only. Signed, short-lived, single-use checkout tickets transfer it to WooCommerce, which validates products/variants/stock and calculates prices. Never trust client totals. WordPress handles payment and account sessions.
- The bridge defaults commerce closed. `EDOCTOR_COMMERCE_READY` and `EDOCTOR_EXPORT_READY` are operator-set only after real settings are validated. No shipping quote means advisor-only checkout; BaridiMob/BaridiWeb orders remain on-hold until human payment confirmation.
- Keep secrets server-side. Public Meilisearch key must be search-only for the products index. Contact data stays in private WordPress requests, not logs or Git.
- Use npm and the committed package-lock for this checkout; the inherited pnpm launcher failed locally. Preserve the pre-existing pnpm lock changes rather than silently restoring them.
- Docker builds standalone Next.js. GitHub Actions tests/builds/publishes commit-tagged GHCR images. Production job uses environment approval and the Coolify application API to update the storefront and search worker to the same commit tag. Both UUIDs identify Docker Image applications, not Compose services. See `DOCS/EDOCTOR-SETUP.md`. Roll back by immutable image digest; preserve search volumes and WordPress backups.
- Run typecheck, functional tests, browser checks, PHP lint, and a production build. Full payment, import, tax and shipping certification requires a staging WooCommerce instance. Never describe those live checks as passed without evidence.
- `npm run test:catalog` builds fictional GraphQL fixtures into `.next-catalog-test`, separately from `.next`, and checks product/variant selection, basket persistence, URL filters and Arabic mixed content on desktop/mobile. Keep fixture builds out of Docker and never substitute their prices, photos or stock for commercial data. The suite restores `next-env.d.ts` after completion.
- `EDOCTOR_RESEARCH_PREVIEW=1` with no GraphQL URL enables the generated research snapshot. All researched references are included, but unknown prices, stock and missing photos remain explicit. A configured GraphQL backend always wins, even during outages. Preview checkout and indexing are disabled. Rebuild when switching modes, and keep build/runtime flags aligned. `seed:generate` prepares the snapshot and validated photo copies; `seed:check` verifies freshness; `test:research` checks this mode in `.next-research-test`.
- Inspect UI with an isolated browser. The user explicitly excluded Brave on their machine. Keep Lighthouse reports local, use three mobile runs and median assertions, and report variation and catalog/fixture scope. A score on an empty catalog cannot certify production performance.

Remaining business inputs: legal identity, domains, support channels, card provider, carrier/zones/delays, export fee schedule, tax/export procedure, guarantees/returns, privacy retention and real suppliers/prices.
